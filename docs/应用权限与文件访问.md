# 应用权限与文件访问（给接手的项目看）

> 结论：**默认不做通用 broker**。应用由面板安装并启动时，用"面板托管"即可与面板**共用 macOS 授权**。
> 只有出现"必须脱离面板独立运行、又需要面板权限"的应用时，才升级到第 4 节的 broker。

## 1. 事实（本项目在真机实测过，不是推断）

| 事实 | 结论 |
|---|---|
| TCC 按 **responsible process 的代码要求**判定，不按 uid（root 也不能绕过） | 授权必须绑到"某个身份"上 |
| 面板拿到授权后，**它的子进程能继承** | 面板启动的应用天然共用权限（已验证：面板能读的可移除宗卷，子进程也能读） |
| 独立进程（自己的 LaunchAgent/Daemon）= **另一个 responsible process** | 要**自己**授权，跟面板的授权无关 |
| 授权绑代码要求；**adhoc 签名的判据含 cdhash** | 未签名的独立应用**每次重打包/升级都要重新授权**（坑 180/184） |
| 固定自签证书签名（`identifier` + `certificate root`，不含 cdhash） | 面板实测 1.4.8→1.4.10 升级**不用重新授权** |

## 2. 形态 A：面板托管（默认，推荐）

应用**由面板安装并由面板启动**，对操作系统而言是面板的子进程 ⇒ 继承面板的授权。

- 面板侧：系统 LaunchDaemon（label `cn.zizpanel.<app>`），可执行文件是**面板自己的二进制**的子命令
  （例如 `zizpanel macsaber-supervise`），它再以**真实用户身份** fork 出应用（`SysProcAttr.Credential`，
  不要用 `sudo`：少一个进程、TCC 归属更干净）。
- 为什么以真实用户跑子进程：文件归属、`say`/`osascript`/`shortcuts`/`pbcopy` 这类**要图形会话**的能力才可用。
- 面板必须做的：启用/打开时**展示这个应用会以面板权限读写哪些路径**（第 3 节），停用/卸载时清理干净，
  并按运行体复核（进程在、健康端点真返回版本），**不许把"plist 写出来了"当成装好**。

**不适用**：用户自己从终端/别的安装器启动的应用。

## 3. 形态 B：同身份守护进程（逃生口）

应用保持独立守护进程，但**用面板那把固定证书 + 面板 identifier 签名** ⇒ 代码要求与面板逐字一致，
面板的授权直接命中它。

- 代价与风险：任何用这个身份签出来的二进制都**继承面板的全部权限**（等于 FDA）。只允许签我们自己的、
  审计过的产物；**绝不能**给第三方包重签这个身份。
- 什么时候用：应用确实不能由面板启动，但又必须共用权限。优先考虑直接改成形态 A。

## 4. 形态 C：通用 broker（v2，**暂不做**）

**触发条件**：出现第一个"必须脱离面板运行、又需要面板权限、且不能同身份签名"的应用时，才立项。

设计要点（届时一次做对）：

1. 面板内建 `zizpanel-broker`：**面板的子进程**（Unix domain socket，0600，仅回环）⇒ 继承面板授权。
2. **每个应用一个令牌**（0600 文件），面板界面里逐应用、**逐路径**显式批准；没有批准一律拒绝。
3. **只放开必要动作**：v2-lite 只做 `stat` / `list` / `open`。
4. **大文件必须传 fd**：面板 `open` 后用 `SCM_RIGHTS` 把文件描述符传给应用，应用自己读写 ⇒
   面板不进入数据路径（否则视频/大文件会把面板变成瓶颈）。
5. **全量审计**：谁、哪个应用、哪个路径、什么动作、成败；面板提供界面可查、可一键撤销。
6. 安全底线：broker 等价于"把面板的权限借出去"，**必须**有调用方校验 + 路径范围 + 审计；
   不满足这三条就不许上线（否则本机任何进程都能让面板替它读任何文件）。

## 5. Linux / 飞牛（fnOS）对应

没有 TCC。同一套设计退化成**运行用户/组 + 文件 ACL**：

- 形态 A ≈ 由面板（或 compose）以**同一个服务用户**启动应用（`user:` / `group_add`）；
- 形态 C ≈ broker 用**同一个 uid/gid** 打开文件再把 fd 传出去（`SCM_RIGHTS` 语义与 macOS 相同）；
- 因此**协议层不需要分平台**：把"授权"抽象成"面板持有的凭据/身份"，macOS 上是 TCC，Linux 上是 uid/ACL。

## 6. 简单场景别上重锤

应用只需要"某个目录"时，**配置文件**就够了（面板写配置、应用自己读，谁都不需要额外权限）：

- 例：**已独立出去的 zizvideo 仓库**（`/Users/zizdog/Documents/DeepSeek/zizvideo`）的 `media_allow_roots`
  （JSON 数组；面板/脚本可直接改，环境变量 `ZV_MEDIA_ALLOW_ROOTS` 可覆盖），
  它另有 `check-access <绝对路径>` 只读动词供面板复核自己的授权（见该仓库 `HANDOVER.md` §4.6）；
- 例：mac军刀 的 `--read-root` / `--write-root`。

**判断顺序**：能靠配置解决 → 就用配置；不能 → 形态 A；还是不行 → 才考虑 B/C。
