## 二、三个独立故障（不是一个）

1. **合成 100% 失败（故障①，根因=解释器被删）**
   `mlx_audio` 懒加载 `tts.generate → sounddevice → ctypes.util` 时抛
   `ModuleNotFoundError: No module named 'ctypes.util'`，而这个异常发生在**已经发出 200 响应头之后**
   → 客户端拿到 200 + 0 字节 body。`/v1/models`、`/v1/audio/voices` 不 import 生成模块，所以一直正常。
   **修**：`brew install python@3.11`（mini 连不上 formulae.brew.sh，改用清华 TUNA 镜像）→ 重建 venv →
   `pip install "mlx-audio[server]"` → 重启服务。验证：直连 8880 → 200 / 119,084 B WAV；经接收端 → 200 / 103,724 B / 1.4s。
2. **推音色样本 500（故障②，根因=面板猜了 `nobody`）**
   `/opt/homebrew/var/run/nginx/client_body_temp` 属主 `nobody`，而 nginx 以 `zizdog` 跑
   （master 非 root、`nginx.conf` 没有 `user` 指令）→ 请求体 > `client_body_buffer_size`(8k) 要落盘却写不进去
   → **nginx 回它自己的 500 HTML 页**（`Content-Type: text/html`）。
   面板 1.3.4–1.3.7 的 `ensureNginxRuntimeDirs` 在 `nginx.conf` 读不到 `user` 时 `worker = "nobody"` 去 chown，
   而且启动/任务收尾/每 2 分钟巡检都会跑 —— **我手动 chown 成 zizdog 后，几十秒内被面板改回 nobody**（日志 20:24/20:25 可证）。
   **修**：属主判据改为运行体（跑着的 `nginx: worker process` 的 uid/gid → 退回 `user` 指令 → 都不行就不改），
   mini 上另加 `user zizdog staff;` 兜底（`nginx -t` 通过）。验证：368KB 样本经 8888 → 200 + 接收端 JSON。
3. **市场"装了显示未装"（故障③，根因=判据不完整 + 缓存不失效）**
   见坑 174：纯 CLI/目录型安装体没有证据、5 分钟缓存装完不失效、brew 探测失败被当空集合。
   mini 上 phpMyAdmin 实际是 **brew 装的 5.2.3**、探测命令本身也正常 ⇒ 你看到"未安装"最可能是
   **刚装完时市场还在用安装前的缓存**。

## 三、为什么"灯全绿"（这是最该修的一点）

- 面板对 Qwen3 TTS 的判据只有"服务记录/plist 在 + `/v1/models` 200"——坏掉的服务**照样答 200**；
- 反代的判据只有"端口在听 + 健康路径通"——**不验大请求体**；
- 市场的判据只有"服务记录/plist/brew"——**不看真实产物**。

三处同源：**判据没贴着"那个能力本身"**。于是"能启动"被当成"能用"，用户看到的是环境完好、实际全坏。
类级规矩已写进 `AGENTS.md` 第三节（判据贴着能力；读不到就拒绝，不许猜默认值）。

## 四、已落地的"不许再犯"机制

| 事实 | 机制 |
|---|---|
| 猜 `nobody` 导致临时目录属主错 | `priv.NginxWorkerOwner`（运行体优先）+ 门禁 `TestNginxWorkerOwner*`、`TestEnsureNginxRuntimeDirsOwnerDiscipline` |
| 市场判据缺产物、缓存不失效、探测失败当空集 | `installed_body.go` + `DetectRuntimeBody` 第三条证据 + 任务收尾失效缓存 + `(map,ok)` 分离；门禁 `installed_body_test.go`、`market_installed_evidence_test.go`、`market_button_state_frontend_test.go` |
| 装完不验能力 | 环境健康巡检（能力探针：解释器不悬空 + `import` 探针 + 端口）+ 登录后醒目横幅（在建） |
| 应用强依赖的 formula 被 autoremove 带走 | 面板所有 brew 命令带 `HOMEBREW_NO_AUTOREMOVE=1`；对关键 formula 执行 `brew pin` |
| 备份任务选项没落库 / 活 WAL 库被直接 tar | 备份/恢复实现（见 `docs/备份与恢复设计.md`）：选项落库 + `VACUUM INTO` + manifest/sha256 |
| 发布时把别人的半成品 `git add -A` 进去 | `tools/publish-release.sh` 发布前**列出**未提交源码并要求 `ZP_ALLOW_DIRTY_PUBLISH=1` 显式确认（坑 177） |
