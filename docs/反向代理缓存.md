# 反向代理缓存（可选，默认关）

> 目标：把"回源一次、之后走本地缓存"做成**通用能力**，任何用户都能拿它搭镜像代理站 /
> 图床前置 / CDN 前置，而不需要为某个站点写专属模块。
> 每个反代规则一个开关 + 上限 + 有效期 + 「清空缓存」。

## 1. 缓存区声明放在哪、为什么

nginx 的 `proxy_cache_path` **只能出现在 `http` 上下文**，而反代规则生成的是 `server` 块
（`vhosts/proxy-<id>.conf`）。所以声明单独放：

```
<brew>/etc/nginx/conf.d/zizpanel-cache.conf     # 面板管理，内容由 get 时生成
```

为什么选它：

- `nginx.conf` 的 `http` 块已经 `include conf.d/*.conf`（WebSocket 升级 map 就是这么放的，
  自愈在 `priv.ensureConfDIncluded`）—— 写这个文件**不需要改 nginx.conf 一个字**；
- 与站点 vhost 目录彻底分开，不会和 `<域名>.conf` 抢文件名，也不会和用户自己的
  `proxy_cache_path` 撞出 duplicate zone（只声明以 `zp_proxy_<id>` 命名的区）。

幂等做法（三条一起保证）：

1. **一个文件、按区名排序整体重写**（临时文件 + rename），同样的规则集永远生成同样的字节；
2. **判据取自磁盘**：声明只为"面板生成的 `proxy-*.conf` 里真的 `proxy_cache <区>` 引用到"的
   区生成 —— 关闭缓存/删规则后 vhost 不再引用，下次生成时声明自然消失；
3. **两阶段写盘**（过渡态安全）：
   - ① 写 vhost 之前：写入 `旧 vhost 引用 ∪ 即将写入的 vhost 引用` 的并集声明
     （旧 vhost 还在磁盘上，少了它的区，提权助手跑的 `nginx -t` 会报 `unknown zone` 并整份回滚）；
   - ② 新 vhost 落盘后：只保留仍被引用的区；文件内容为空时**删除文件**
     （没有任何规则开缓存 = 与升级前完全一致）。

每次写盘都由提权助手做真实 `nginx -t`；删/停用后的收敛路径另外单独跑一次
`nginx-test`，失败即回滚 vhost + 声明文件。

## 2. 归属（铁律：拿不到就别猜）

缓存目录 `<DataDir>/proxy-cache/<zp_proxy_<id>>`：

- 建目录后把整棵树 `chown` 给 **运行中的 nginx worker 用户**（判据：运行中的 worker 进程 →
  `nginx.conf` 的 `user` 指令，见 `priv.NginxWorkerOwner`）；
- 读不到 worker 用户就**返回错误**，绝不猜 `nobody`（AGENTS 坑 173）；
- 目录本身一定建出来 —— nginx 启动时若 `proxy_cache_path` 的父目录不存在会直接 `[emerg]`；
- 为什么必须 `chown`：写 vhost 的助手以 **root** 跑 `nginx -t`，而 `-t` 会创建缓存区目录
  （root 属主），nginx worker 随后写不进去 —— 与 nginx 日志目录是同一个坑。

## 3. 接口 / 字段契约

字段**不进 `proxies` 表**，与「需要用户名密码」同一条约定：真相在 `settings` 表
（键 `proxy_cache.<id>`，值一行 JSON `{"enabled":bool,"size":"1g","valid":"1h"}`）。
这样不抢 store 的 schema（`internal/store/**` 不在本轮文件域），一条规则也只有一份真相。

复用现有路由（不新增路由）：

| 动作 | 请求 | 说明 |
|---|---|---|
| 开/关缓存、改上限/有效期 | `POST /api/v1/proxies/{id}` + `cache_enabled` / `cache_size` / `cache_valid` | 与规则其它字段一次提交；同步（秒级）返回 |
| 清空该条缓存 | `POST /api/v1/proxies/{id}` + `cache_clear: true`（**只带这一个字段**） | 只删文件、不重写配置、不重载 |

- `cache_size`：`256m` / `1g` / `5g` / `10g` / `50g`（正则 `^[0-9]{1,5}[kmg]$`，归一化小写），
  默认 `1g`；
- `cache_valid`：`10m` / `1h` / `1d` / `7d` / `30d`（正则 `^[0-9]{1,4}[smhd]$`），默认 `1h`；
- 非法格式返回 **400**，不落库、不写盘；
- 响应里 `cache` 对象是**回读生效值**：`enabled/size/valid/zone/dir/dir_exists/verified/note`。
  `verified=true` 要求 conf.d 声明与 vhost 的 location 指令都在磁盘上对得上；读不到就写
  "未复核"并给出原因（绝不只说"已保存"）。

同步 vs 任务中心：**同步**。它与"保存规则"是同一类动作（一次提权写盘 + `nginx -t` +
reload + 请求级复核，秒级），且回滚建立在请求上下文的快照上；塞进任务中心会把一次原子
写盘拆成"请求 200 但任务还在跑"，反而制造"配置/数据库谁说了算"的不一致。

## 4. 生成的配置片段

关闭（与加缓存之前**逐字一致**，不写任何 `proxy_cache`）：

```nginx
location / {
    proxy_pass http://192.0.2.10:8090;
    ...
    proxy_http_version 1.1;
    proxy_connect_timeout 60s;
    proxy_send_timeout    3600s;
    proxy_read_timeout    3600s;
    proxy_buffering       off;
    proxy_request_buffering off;
}
```

开启（`vhosts/proxy-7.conf`）：

```nginx
location / {
    proxy_pass http://192.0.2.10:8090;
    ...
    proxy_http_version 1.1;
    # 反向代理缓存：回源一次，之后走本地缓存（缓存区在 conf.d 声明）
    proxy_cache zp_proxy_7;
    proxy_cache_valid 200 301 302 1h;
    proxy_cache_bypass $http_upgrade;
    proxy_no_cache $http_upgrade;
    proxy_connect_timeout 60s;
    proxy_send_timeout    3600s;
    proxy_read_timeout    3600s;
    proxy_buffering       on;          # 必须 on：off 时 nginx 根本不写缓存
    proxy_request_buffering off;
}
```

`conf.d/zizpanel-cache.conf`（http 上下文）：

```nginx
# 由 ZizPanel「反向代理缓存」生成 —— 请勿手工编辑（会被面板覆盖）
# proxy_cache_path 只能在 http 上下文；本文件由 nginx.conf 的 include conf.d/*.conf 加载。
proxy_cache_path /opt/zizpanel/data/proxy-cache/zp_proxy_7 levels=1:2 keys_zone=zp_proxy_7:10m max_size=1g inactive=1h use_temp_path=off;
```

- `proxy_buffering on` 是硬要求：本机 nginx 1.31.5 实测 `off` + `proxy_cache` 时同一 location
  三次全 MISS、上游被打三次 —— 不开缓冲的"缓存"是谎报成功。
- `inactive=<有效期>`：超过有效期没被访问的项被淘汰；`proxy_cache_valid` 决定"多久算新鲜"。

## 5. 怎么验证（真实输出见本轮汇报）

```bash
export GOPROXY=https://goproxy.cn,direct
go test ./internal/proxies/ -run Cache -count=1 -v
go test ./internal/web/  -run Cache -count=1 -v
node tools/check-js-syntax.mjs
```

- `TestProxyCacheRealNginx`：临时 prefix + 临时配置起**真 nginx**；`nginx -t` 通过；
  反例（同一条 `proxy_cache_path` 放进 server 块）必须报 `"proxy_cache_path" directive is not
  allowed here`；同一 URL 第二次 `X-Cache-Status: HIT` 且上游只被打一次；不同 URL / 另一条规则
  必须回源；两个规则的缓存目录里真的落了文件。
- `TestEnsureProxyCacheDirOwnsToRealWorker` / `RefusesToGuessWorker`：真实 `stat` 回读归属；
  拿不到用户时失败且错误文本里不出现 `nobody`。
- `TestCacheZonesIdempotentEnableDisable`：连续两次启用/关闭字节不变、无重复 `keys_zone`、
  关闭后声明文件被删除。
- `TestRuleGenerateCacheOffIsByteIdentical`：关闭时输出与无缓存字段逐字一致。

## 6. 已知限制（如实标注）

- **开启缓存会打开响应缓冲**（`proxy_buffering on`，nginx 缓存的硬要求）：该规则下的
  SSE / 长连接流式输出会从"边收边发"变成"先攒后发"。要流式就不要给它开缓存。
- 改**上限**只改 conf.d 的 `max_size`：`nginx -t` 与 `reload` 都接受（不会报错），
  但"已经在内存里的共享区是否立刻按新 max_size 淘汰"没有逐项验证；
- 关闭缓存**不删**磁盘上的缓存文件（用「清空缓存」删）；删除规则时会连带清掉并如实
  上报释放量；
- 缓存命中与否不做探测（nginx 的 `$upstream_cache_status` 只在响应头里），
  面板只回读"配置是否生效"。
