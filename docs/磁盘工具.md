# 磁盘工具（面板内）

> 面板侧栏 **系统 → 💾 磁盘**。后端 `internal/web/api_disks.go`（枚举/挂载/fstab）、
> `internal/web/api_disks_ops.go`（抹盘/格式化/建卷/删卷/重命名）、
> `internal/web/api_disks_plist.go`（plist 解析）；前端 `internal/web/assets/js/disks.js`。

## 一、能做什么

| 能力 | 命令 | 说明 |
|---|---|---|
| 查看磁盘/分区 | `diskutil list/info -plist` | 设备名、整盘/分区、容量、文件系统、卷名、挂载点、可移除/外接、加密、SMART、总线与型号 |
| 挂载 / 卸载 | `diskutil mount/unmount <id>` | **回读挂载点确认**，不把退出码当结论；不强卸 |
| 开机自动挂载 | 写/删 `/etc/fstab` | 原子写 + 备份；格式见下 |
| 抹盘 / 格式化 | `diskutil eraseDisk/eraseVolume <格式> <卷名> <id>` | 整盘重建分区表，或只重建某个分区/卷 |
| 新建 APFS 卷 | `diskutil apfs addVolume <容器> APFS <卷名>` | **不要求容器为空**；不动已有卷 |
| 删除 APFS 卷 | `diskutil apfs deleteVolume <id>` | 只删该卷及其数据 |
| 卷重命名 | `diskutil rename <id> <新卷名>` | 只改名，不动数据 |

**唯一不做的**：不动系统盘相关设备（见"安全边界"）。其余操作对**非系统盘**开放。
挂载/卸载/开机自动挂载是**同步 + 回读**；抹盘/建卷/删卷/重命名是**任务中心任务**
（202 + `task_id`，进度与日志在顶栏「任务中心」里实时看，关掉窗口任务照跑），
完成后页面刷新磁盘列表并展示回读摘要（卷名 / 容量 / 挂载点 / 容器剩余空间）。

## 二、文件系统与取舍（界面里同样写明）

| 选择 | diskutil 格式 | 取舍 |
|---|---|---|
| **APFS** | `APFS` | macOS 原生、快、支持快照/加密；**Windows/Linux 不能原生读写**。本机镜像盘推荐 |
| **HFS+** | `HFS+` | 旧格式；非 Apple 平台同样要第三方工具；不推荐新盘 |
| **exFAT** | `ExFAT` | macOS / Windows / Linux 都能读写，适合"插拔硬件做备份/迁移"；代价：**无日志**（意外拔盘更易损坏）、权限语义弱 |
| **MS-DOS (FAT32)** | `MS-DOS FAT32` | 全平台兼容；但**单文件 ≤ 4 GiB** —— 镜像包/模型经常超过，**不适合做镜像盘** |
| 保持现状（不格式化） | —— | 不执行任何格式化；选了它则提交按钮不可用（没有可做的写操作） |

## 三、安全边界（怎么保证绝不碰系统盘）

1. **白名单**：写操作的目标 `id` 必须来自 `diskutil list -plist` 的 `AllDisks`，且形如
   `disk9` / `disk9s2` / `disk4s1`；不存在 → 404，格式非法 → 400。
2. **系统盘保护集合**（`computeProtected`）沿关系传播到不动点，命中即 403：
   `Internal`/`OSInternalMedia` 为真、挂载点 `/` 或 `/System/Volumes/*`、`/` 所在卷、
   以及它们的父/子分区与以它们为物理存储的 APFS 容器（及其卷）。
3. **两道 TOCTOU 校验（`beginDiskWrite`）**：真正调用 `diskutil` 写命令前，
   重跑 `diskutil list` + 全设备 `info`，并单独再 `info` 一次目标，确认
   ① 设备仍在列表里、② 仍是非系统盘、③ UUID 与容量和确认框里看到的一致。
   任何一项对不上 → **409**，提示"盘可能被换过/状态变了，请刷新后重试"。
   这道校验跑**两次**：handler 的同步预检（决定要不要建任务）与任务体里真正执行前
   （防止"排队等任务中心调度期间盘被换掉"）。
4. **被拒时不会创建任务、也不会执行任何 `diskutil` 写命令**（有测试断言
   拒绝路径 `Tasks.List()` 为空，且 `mount/unmount/eraseDisk/eraseVolume/apfs addVolume/apfs deleteVolume/rename` 都没跑过）。
5. **强确认**：抹盘/格式化/建卷/删卷/重命名都要求用户**手动输入设备标识** + 勾选警告 +
   在界面上看到"受影响的卷清单"；后端**再校验一次**（不信前端）。
6. **审计**：每个成功/失败都写 `disk_erase` / `disk_volume_create` / `disk_volume_delete` /
   `disk_volume_rename` / `disk_mount` / `disk_unmount` / `disk_auto_mount` / `disk_list`；
   动作前把**卷与容量快照**（`before_state`）记进审计：成功时它是任务结果的 `steps` 首行
   （`launchTask` 会把 `*services.InstallResult` 的 Steps 写进审计），失败时它在错误文本里
   （`before={...}`），便于事后追溯。
7. **无 GUI 授权**：root 的 launchd 里 root 直接跑 `diskutil` 不需要任何弹窗；代码里
   **禁止**出现会弹授权窗的脚本或提权 API（`api_disks_test.go` 的 `diskForbiddenGUIs` 有 grep 门禁）。
   加密卷 `Locked` 时挂载、为加密卷写自动挂载 → **409**，明确说"需人工介入，无头环境不可用"。
8. 所有 `diskutil` 写命令 **60s 超时** + stderr 原文；失败/超时后**回读真实状态**再给结论
   （"设备可能已被改到一半，请复查"）。

## 四、fstab 格式（查证 `man 5 fstab` 并实测写入路径）

```
# zizpanel auto-mount <卷 UUID>
UUID=<卷 UUID> <挂载点> <文件系统类型> rw 0 2
```

第一字段只用 `UUID=`/`LABEL=`（man 明确要求 APFS 不能用块设备名）；`rw` 默认即自动，
`noauto` 才是"不自动挂载"；挂载点里的空格按 fstab(5) 转义成 `\040`。删除条目时只删本卷那一行
（连同标记行），**其它行一字不动**，先备份到 `/etc/fstab.zizpanel.bak`。

## 五、API 契约

```
GET  /api/v1/system/disks
     data = { list:[{disk:{...}, partitions:[{...}], init:{eligible,container_ref,...}}],
              protected:[{id,reason}], filesystems:[{key,label,diskutil_format,vfstype,note}],
              root_device, is_root, fstab_path, fstab_entries, fstab_readable, fstab_error?,
              custom_mount_base,   # 「挂载到自定义挂载点」允许的前缀（<安装根>/mnt）
              notes:[...], collected_at }

# 危险动作：**走任务中心**（立刻 202 + data.task_id，进度/日志/中断复用任务中心；
#   完成后 result = {app,name,message,steps}，steps 里带 before/after 与回读摘要）。
#   均需 body.confirm == 路径里的 {id}，并建议带 expect_uuid/expect_size 做 TOCTOU 校验。
#   确认不匹配 / 系统盘 / 身份不一致 → 当场 4xx，**不创建任务**。
POST /api/v1/system/disks/{id}/erase          body{filesystem,name,confirm,expect_uuid,expect_size}
POST /api/v1/system/disks/{id}/volume-create  body{name,confirm,expect_uuid,expect_size}
POST /api/v1/system/disks/{id}/volume-delete  body{confirm,expect_uuid,expect_size}
POST /api/v1/system/disks/{id}/volume-rename  body{name,confirm,expect_uuid,expect_size}
#   202 响应：data={task_id,title}；任务结果见 GET /api/v1/tasks/{task_id}
#   （data.task.result.message / data.task.result.steps），日志走 SSE。
#   任务日志里的命令**从 cmd.Args 派生**（不手写标签），完成后回读并写入：
#   卷名 / 容量 / 文件系统 / 挂载点与挂载状态 / 容器剩余空间。
# init-volume 是 volume-create 的旧名（第一版接口），保留为别名。

# 安全动作（保持同步 + 回读，不走任务中心）：
POST /api/v1/system/disks/{id}/mount         body{mount_point?}  data={id,action,verified,mounted,mount_point,command,stdout,stderr,message}
#   mount_point 非空 → `diskutil mount -mountPoint <dir> <id>`，只接受 <安装根>/mnt/ 下的
#   子目录（不存在则先建；解析软链接后仍须在该前缀内）。用于绕开 macOS 对外接卷的隐私
#   保护，见第七节。为空/不带 body 时行为不变（挂到 /Volumes）。
POST /api/v1/system/disks/{id}/unmount       同上
POST /api/v1/system/disks/{id}/auto-mount    body{enabled}  data={... ,reboot_required,reboot_note,message}
```

全部 `requireAuth`（写操作另有 `X-CSRF-Token` 双提交，由 `requireAuth` 统一处理）。
`filesystem` 取 `apfs` / `hfs+` / `exfat` / `fat32` / `keep`。

## 六、验证到什么程度（诚实标注）

- **本机真机已验证**：
  - 只读枚举（真实 `diskutil list/info/apfs list`）；
  - `mount`/`unmount` 真实成功并回读（**本机 admin 用户不需要 root**）；
  - **用磁盘映像真跑** `eraseDisk` / `eraseVolume` / `apfs addVolume` / `apfs deleteVolume` /
    `rename`（`hdiutil create/attach` 造一块映像盘，非 root 也能执行，操作后 `hdiutil detach` 收尾）；
  - 系统盘/受保护设备的写动作全部 403 且未执行命令；TOCTOU 不一致 409；
  - 前端禁用、强确认、0 JS 错误。
- **未验证（需在 root 正式面板 / 需重启）**：
  - **真实外接盘（非映像）的整盘抹掉**（不敢拿用户的 1T 盘做破坏性实测）；
  - 写 `/etc/fstab`（非 root 被系统拒绝，见错误原文；root 面板才能写）；
  - "开机自动挂载在重启后生效"（本机绝不重启）；
  - **「挂载到自定义挂载点」是否真能绕开 TCC**（需要正式 root 面板 + 外接盘，见第七节）。
- 预期命令（供 root 面板核对）：
  `diskutil eraseDisk <格式> <卷名> <整盘>` / `diskutil eraseVolume <格式> <卷名> <分区>` /
  `diskutil apfs addVolume <容器> APFS <卷名>` / `diskutil apfs deleteVolume <卷>` /
  `diskutil rename <卷> <新名>`，fstab 条目 `UUID=<uuid> <挂载点> <vfstype> rw 0 2`；
  自定义挂载点 `diskutil mount -mountPoint /opt/zizpanel/mnt/ZPMirror disk4s1`。

## 七、外接盘访问被 macOS 拒绝（TCC）怎么办

**现象**：文件管理打开 `/Volumes/<卷>` 报
`打开目录失败: open /Volumes/<卷>: operation not permitted`。

**根因**：macOS 隐私保护（TCC）。面板以 **root 的 LaunchDaemon** 运行、没有用户会话，
读写 `/Volumes` 下的外接盘/可移除卷会被系统直接拒绝（EPERM/EACCES）。文件管理接口按
**真实 errno + 路径前缀**判断（不匹配字符串），命中时返回 **403** 并附完整指引
（`internal/web/api_files.go::volumeTCCPath`）。

**解法（面板自己就能做，不需要任何人工授权）**：把卷挂到 `/Volumes` 之外再访问 ——
**挂载本身不受这条隐私保护限制**。

- 界面：**磁盘 → 该卷所在行 → 「挂载到自定义挂载点…」**，默认
  `<面板安装根>/mnt/<卷名>`（如 `/opt/zizpanel/mnt/ZPMirror`；目录不存在会自动创建）。
  后端只接受 `<面板安装根>/mnt/` 下的子目录，且解析软链接后再确认没越界。
- 等价命令：`diskutil mount -mountPoint /opt/zizpanel/mnt/ZPMirror disk4s1`
  （`disk4s1` 换成 `diskutil list` 里的卷标识）。
- 挂载后回读 `diskutil info` 的 `MountPoint` 确认；文件管理的「位置」下拉会出现该路径。

> 为什么不让用户去「系统设置 → 隐私与安全性 → 完全磁盘访问权限」里手动添加面板：
> 那需要**在有屏幕的机器上人工点一次**，无头/远程场景做不到。人工授权是 Apple 的另一条路，
> 这里不作为给用户的指引。

⚠️ **诚实标注（未实测）**：「换挂载点即可绕开 TCC」这条路径**尚未在真实 root 面板 + 外接盘上
实测**（需要正式面板 + 外接盘）。真实 root 面板下的 EPERM 也未在开发会话里复现 ——
本机调试实例（`make run-local`）跑在用户会话里，走不到这条拒绝路径。
