# 已修复的典型坑

> 每条含**现象/根因/修法/门禁**四要素；只保留还能防复发的东西 —— 过时的合并或删除（判据见 `AGENTS.md` 第六节）。
> 编号不重排（保持历史 ID，供代码/文档引用）；编号不连续表示该条已合并或删除。
> 会伤到使用者的（安装卡住、谎报成功、破坏用户环境）在 `AGENTS.md` 第三节另有摘要。

1. **CPU 采集**：Apple Silicon 上 `sysctl kern.cp_time` 已移除（CPU 恒 0），`ps` 的 `%CPU` 也是瞬时值（面板 fork `top` 的那一刻把自己谎报成高占用）→ 主路径解析 `top -l 1 -n 0`，`kern.cp_time` 仅兜底；进程占用改用两次 `cputime` 采样差值。门禁：`TestParseTopExtractsAllMetrics`、`TestCollectOnThisMachine`、`TestParseCPUTime`、`TestProcSamplerFirstSampleIsZeroThenReal`。
3. **两个 bash 陷阱**：`$VAR` 后紧跟中文标点会被并进变量名（`set -u` 直接退出）；`local` 写在循环体内每轮重声明并清空。→ 一律 `${VAR}` 显式引用，`local` 移出循环；字节级扫描器 `tools/check-shell-vars.py` 接入 `make check`（只覆盖前一条）。门禁：`tools/check-shell-vars.py`。
5. **受保护文件（sudoers 0440）无法直接重定向覆盖；权限/属主不对 sudo 拒绝加载** → 写临时文件 + 原子替换 + `visudo -c`，权限 0440、`root:wheel`，语法错就撤销。门禁：`tools/sandbox-install-test.sh`（只断言内容，不断言原子替换）。
6. **root 下 `$HOME` 是 `/var/root`：`status` 硬编码配置路径会误报未初始化，安装脚本也找不回真实用户** → `status` 显式传 `--config <DataDir>/config.json` 并跟随 `ZIZPANEL_ROOT`；安装脚本按 `SUDO_USER` → `id -un` → `/dev/console` 属主 找回真实用户/家目录。门禁：`tools/sandbox-install-test.sh`。
7. **macOS 上 `/var` 是 `/private/var` 的软链接 → 路径前缀校验误判"越界"** → 判定前两侧都 `EvalSymlinks`，目标不存在时单独处理。门禁：`TestResolveBlocksSymlinkEscape`、`TestResolveMissingTargetStaysInside`、`TestWriteBlocksSymlinkEscape`。
8. **CSRF 缺头时回退读 Cookie，双提交形同虚设（浏览器自动带 Cookie）** → `csrfOK` 只认 `X-CSRF-Token` 头（值取可读的 `zp_csrf` cookie），写接口缺它一律 403。门禁：`TestCSRFProtection`、`TestBaseEnvInstallRequiresCSRF`。
9. **面板以 root 跑把网站根算成 `/var/root/www`** → plist 显式传 `ZIZPANEL_USER`，`PanelUser()` 优先读它。门禁：`tools/sandbox-install-test.sh`。
10. **Homebrew 拒绝以 root 运行；`sudo` 会清空环境** → brew 查询走 `sudo -n -u <真实用户>`；注入环境必须写成 `sudo -n -u <user> /usr/bin/env KEY=VAL …`（赋值在 `sudo -u` 之后、`env -u` 之前）；安装脚本用 `brewSudoShim` 冒充 sudo（见 86）。门禁：`internal/services/brew_fallback_test.go`。
11. **`kill(pid, 0)` 探测 root 进程返回 EPERM → 服务在跑却报"已停止"** → 存活判据用 `ps -p <pid>`，launchd 另用 `launchctl print`。门禁：无（launchd 侧有 `internal/priv/launchd_test.go`）。
12. **`mkcert -install` 在 SSH/非图形会话等 GUI 授权永久阻塞，安装卡死；没装 mkcert 时每次还白等 20 秒** → 先查候选路径，没有直接自签并给手动指引；有才 20 秒超时 + 自签回退。门禁：无。
13. **含 `fastcgi_pass` 的片段留在 http 级 `conf.d/` 使 nginx 无法启动** → `MigrateFPMInclude` 迁到 `includes/` 并改写引用。门禁：`TestBuildDefaultVhostUsesSocketEndpoint`。
14. **反代引用未定义的 `$connection_upgrade`，一建反代站 `nginx -t` 就报 unknown variable** → 写 `conf.d/upgrade-map.conf` 并保证 include，被 `nginx -t` 拒后自动补齐重试。门禁：`TestWriteVhostHealsNginxEnvAndRetries`、`TestIsNginxEnvVarErr`。
15. **反代强制 HTTPS 的面板时用了 `http://` → 返回 400；https 上游缺 SNI** → `https://` + `proxy_ssl_verify off` + `proxy_ssl_server_name on`。门禁：`TestHTTPSUpstreamGetsSNI`、`TestHTTPUpstreamHasNoSSLLines`。
16. **子路径部署两个坑**：`proxy_pass` 未剥离前缀 → 后端收到 `/_panel/api/...` 并 307（改 `rewrite … break` + 无 URI 的 `proxy_pass`）；前端用绝对路径 → 全 404（改相对路径 + 入口 301 补末尾斜杠）。门禁：无。
18. **DOM 构建器静默丢内容/冒字面量**：`h(spec, node)` 把 DOM Node 当 props → 弹窗内容整体消失；`Element.append(null)` 渲染成文本 "null" → `h()` 把 Node/数组识别为子节点，`append()`/`appendAll()` 过滤 null/undefined/false（保留 0 与空串）。门禁：`tools/uitest.mjs`。
20. **SSE 进度流被 nginx 缓冲 → 日志成批到达、看着像卡住** → 响应加 `X-Accel-Buffering: no`，反代片段 `proxy_buffering off`。门禁：无。
21. **`launchctl load` 退出码多次谎报成功** → 改 `launchctl print` 真查 state/pid，并以端口探活复核终态。门禁：`TestLaunchUnloadVerifiesEndState`、`TestLaunchStatusProbesUserAndGUIDomains`、`TestLaunchLoadPicksWorkingDomain`。
22. **phpMyAdmin 错误页 HTTP 状态也是 200** → 健康判据读页面内容（`phpMyAdminLooksOK`/`phpMyAdminErrorIn`），不看状态码。门禁：`TestPHPMYAdminLooksOK`、`TestDescribePMAFailure`。
23. **构建/门禁的退出码会静默骗人**：`go build … | head`、`make check | tail`、`;` 串接、磁盘满、`-X` 在 `-trimpath` 下失效（发布包没内嵌公钥、退出码仍 0）；两次 `make release` 哈希本就不会字节一致（`BuildTime`）。→ 固定 `make check > /tmp/check.log 2>&1; echo EXIT=$?`；构建步骤必须查退出码；`make release` 运行产物核对公钥，以 `manifest.json` 的 sha256 为准。门禁：`make release` 的产物公钥核对（退出码类无专项门禁）。

174. **"装了却显示未安装 / 不在已安装里 / 还显示安装按钮"**（图片压缩 libvips 装好没变化、phpMyAdmin 一直"未安装"）：`installed` 的证据只有三条（面板服务记录 / `/Library/LaunchDaemons` plist / `brew list --versions`），而**纯 CLI 应用**（vips/ffmpeg/python3.x）与**目录型安装体**（phpMyAdmin 的 `share/phpmyadmin`）三条全不成立；已装 formula 是 5 分钟 TTL 缓存，安装/卸载任务结束时**没有任何地方让它失效**；`InstalledFormulaVersions` 失败时返回空集合，被当成"这台机器什么都没装"缓存 5 分钟。→ `internal/services/installed_body.go` 给条目声明**真实产物**（可执行文件要存在+有执行位；目录型要目录+入口文件；悬空软链不算）作第三条证据；`(map, ok)` 区分"没查成"与"没有"（失败 30 秒重试、不覆盖旧结论，前端标「⚠ 未能复核已装软件」）；任务收尾只对 install/uninstall/site-install 失效缓存；"凭目录判已安装"必须配"卸载时真的移除那个目录"。门禁：`installed_body_test.go`（遍历整个 `Catalog()`）、`market_installed_evidence_test.go`、`market_button_state_frontend_test.go`。

180. **macOS「可移除宗卷」TCC 保护按『卷』判定，与挂载路径无关**：实测挂到 `/Volumes` 之外**成功**但仍 `operation not permitted`（系统日志 `kTCCServiceSystemPolicyRemovableVolumes` + `record_denial`）；后台 LaunchDaemon 有交互会话时会弹窗、没人在场时被静默记 denial；子进程能读是**继承面板（responsible process）**刚拿到的授权，不是 uid 501 天生可以；授权绑二进制的**代码要求** —— adhoc 签名判据含 `cdhash`，所以**弹窗点允许与系统设置开关都一样升级即失效**（1.4.5→1.4.6→1.4.7 实测），唯一出路是稳定证书签名（见 184）。→ 判据 = 路径落在 `files.NonSystemVolumeMounts()` 的某个挂载点之下 + `tccSolution()` 给两条路（弹窗点「允许」/ 系统设置 → 隐私与安全性 → 完全磁盘访问权限 → 面板二进制；站点/镜像站读盘还要给 nginx）；前端删「挂载到自定义挂载点」入口（后端 API 能力保留）；**换挂载点不是解法**。门禁：`api_files_tcc_test.go`（含"不得出现挂载点解法 / 连询问窗口都不会弹"的反向断言）。教训："某个系统限制看起来是按路径的"是最容易想当然的一类假设，没实测的系统行为，文案里不能出现祈使句。
181. **门禁的样本必须寿命长于测试**（`TestProcessAliveForRootProcess` 从 `ps` 现抓第一个 root 进程，它会在判定前退出 → `make check` 偶发红，且与当轮改动无关）→ 样本换成 **PID 1**（root、永远在，普通用户向它发信号正好拿到 EPERM）；再扫别的 root 进程时只记日志、不计失败。同类第二例：导出→导入→导出比对只排除了 `exported_at`，而导入会**必然重算** `created_at`，跨秒边界时假失败 → 把必然重算的时间字段一并排除，其余字段继续逐字段严格比对（别为了躲一个 flake 把整条门禁改松）。门禁：`TestProcessAliveForRootProcess`、`TestNavExportImportRoundTrip`。
184. **"一次授权长期可用"要靠固定证书签名 —— 已实测成立**：授权绑在代码要求上，adhoc 签名（判据 `cdhash H"…"`）每次构建都变 ⇒ 每次升级都要重新授权（用户提出"做一个专门访问磁盘的工具，面板升级它不升级"，方向对，但面板 `exec` 起的子进程会继承面板身份，那种助手必须做成**独立 LaunchDaemon** 且从此不能再改，工程量大得多）。→ 给发布二进制做**稳定签名**：自签代码签名证书 + `security import` + 受信任导入（证书与私钥必须进**同一个**钥匙串，否则身份配不上）；判据变成 `identifier "com.zizpanel.panel" and certificate root = H"<证书指纹>"`（**不含 cdhash**）；1.4.8（签名）→ 用户开一次完全磁盘访问 → 升到 1.4.9（cdhash 已变）**仍然 200，无需重新授权**。落地：`make release` 走 `tools/codesign-release.sh`（**判据含 cdhash 就拒绝产出**）、证书公钥随包分发、`install.sh` 以 root 导入系统钥匙串并设信任（失败如实报）、`uninstall.sh` 撤销信任；安装脚本**先问"会不会用外接盘"**（默认不用 ⇒ 全程不碰外接卷、不弹任何窗），只有说"会用"才走"现在插盘 + 点一次允许"，门禁四条（默认不用 / 会用 / 远程 / 不写标记）。门禁：`tools/codesign-release.sh`、`tools/sandbox-install-test.sh`。⚠️ **未解决/未验证**：brew 的 **nginx** 不能重签，自身升级后授权仍失效（后续做镜像站时用"我们自己签名的副本或自研极简服务"替代）；`install.sh` 的证书信任导入需要 root，**本机没有 root，这一步未在真机验证**。

198. **写死在目录里的产物 sha256 会随源码漂移**：应用市场条目里的 sha256 是打包时算的，源码再动（并行子代理继续加工具）就让哈希失效 → 用户点安装第一步校验就失败，而门禁只锁「版本/声明一致」，不会自动重算哈希。→ 任何改动该软件源码后必须重跑打包脚本并更新常量（`make macsaber-release` → `internal/services/macsaber.go`）。

202. **自带应用做成独立守护进程会变成另一个 responsible process，TCC 授权不能共用**：mac军刀原先是用户级 LaunchAgent（`cn.macsaber.web`，plist 在 `~/Library/LaunchAgents/`），而 macOS 的隐私授权按 responsible process 的**代码要求**判定 —— 面板（root LaunchDaemon + 固定自签证书，判据 `identifier + certificate root`）拿到的授权只覆盖它自己与它的子进程；用户级 agent 是另一个 responsible process，要**单独授权**，而 macsaber 二进制未签名（Go adhoc `Identifier=a.out`）⇒ 判据含 cdhash ⇒ **每次重打包/升级都要重授**。→ 把自带应用做成**面板自己的子进程**：系统级 LaunchDaemon `cn.zizpanel.macsaber`（plist 在 `/Library/LaunchDaemons/`，root:wheel 0644、**不写 UserName**）执行 `<面板二进制> macsaber-supervise`，supervisor 以 root `fork` 后按 `SysProcAttr.Credential` 直接 setuid/setgid 到真实用户（**不经 sudo**：中间多一个 setuid 进程会把 responsible process 判定带偏），读根改成真实用户家目录（权限来自面板）。安装时先 bootout 旧用户级 agent 并删其 plist（否则两个实例抢 8895，新的起不来）；卸载 bootout system 域 + 删新旧两份 plist + 删 `/opt/macsaber` 并**复核**目录/plist/端口都干净。门禁：`internal/services/macsaber_test.go`（plist 参数顺序 + 无 UserName + `plutil -lint`、迁移夹具、卸载终态、幂等）、`cmd/zizpanel/macsaber_test.go`（子进程参数来自真实用户路径 + `Credential` uid/gid、拒绝非回环/非 root/非绝对路径）。⚠️ **未验证**："TCC 授权真的被子进程继承"只能在真机当面验（反例：终端直接跑 `/opt/macsaber/bin/macsaber` 读 `/Volumes/ZPMirror` 应被拒；正例：supervisor 拉起的同一个二进制应能读且不弹窗）。同一结论适用于 zizvideo：面板托管 ⇒ 继承面板授权、与面板**共用文件权限**（模块自己的端口与数据目录仍各归各的，媒体根不进卸载路径）。
203. **MySQL 的配置文件会把 MariaDB 直接卡死在启动前**：Homebrew 的 `/opt/homebrew/etc/my.cnf` 里有 MySQL 专有项 `mysqlx-bind-address=127.0.0.1`（还有 `mysqlx-*` 一族），MariaDB 不认 ⇒ `mariadb-install-db` 直接 `unknown variable ... Aborting`、init 失败、服务起来也没有数据目录、3306 没人听（看退出码只会以为"装好了"）。→ 换引擎前先处理共享配置（注释掉 `mysqlx-*`，备份原文件）；判据要看"3306 有没有在听 + `select version()` 有没有回 MariaDB"，不是看 `brew services started`。门禁：`tools/system-services.sh` 的引擎分支 + 面板引擎解析。
204. **同一台机器上 MySQL 与 MariaDB 天生冲突：默认共用 `/opt/homebrew/var/mysql` 与 3306**（两个 formula 都 `-DMYSQL_DATADIR=#{var}/mysql`）⇒ 不能同时跑，也不能"装了先放着再切"（切换时 datadir 会被原地升级，回退必须走 dump/restore，MySQL 8 再也读不回来）。→ 面板必须**拒绝**在另一个引擎运行时装/起本引擎，并给出人话出路（先停对方），**绝不许自动停用户的库**；切换的标准动作是：`mysqldump --all-databases`（含 routines/triggers/events）→ 停旧 → 移开旧 datadir（保留，别删）→ 初始化新引擎 → **沿用原 root 口令**（站点与面板的配置就都不用改）→ 导入（去掉只有 MySQL 8 才有的 `utf8mb4_0900_*` 排序规则）。门禁：护栏 9 例 + 引擎解析三态。
205. **"两个引擎都装着"时不许挑默认值**：数据库页要按 3306 上**真正在跑的进程名**判当前生效引擎（`mariadbd` → MariaDB、`mysqld` → MySQL），判不开就如实报"未复核"；客户端二进制同时认 `mysql/mariadb`、`mysqldump/mariadb-dump`。本机实测：MySQL 8.4 的客户端连 MariaDB 13 完全可用（协议兼容），所以面板在未适配时也能连——但**一旦把旧 keg 卸掉就会断**，所以路径解析必须贴运行体。坑 163（归属）同理：别靠"通常在哪"。
206. **MariaDB 的 `mysql.user` 没有 `account_locked` 列**：面板"数据库 → 用户"那条 `SELECT ... account_locked ...` 在 MariaDB 上直接 `ERROR 1054 Unknown column 'account_locked'`（真机实测 13.0.2）。→ 先取服务端 `SELECT VERSION()`（Client 内只查一次并缓存），版本串含 `mariadb` 就换 MariaDB 兼容 SQL，**MySQL 那条逐字保留**；读不到的字段如实标「锁定状态不支持」，**绝不把读不到的 false 显示成"正常"**。同类提醒：MariaDB 的 `mysql`/`mysqldump` 兼容名会在 **stderr** 打 `Deprecated program name…`（成功时无害，失败时会出现在原始错误里，别当成失败）。门禁：`TestListUsersOnMariaDBUsesCompatibleSQL`、`TestListUsersOnMySQLKeepsLockedColumn`。
207. **未提交的新机制被并行代理删掉 = 无法用 git 恢复**：权限页那套"外部应用条件授权入口"当时是未跟踪状态（`?? internal/permissions/`），另一个**拿旧口径**的代理把它删了并改写了同目录文件 ⇒ git 里没有任何副本，只能从被删代理的**会话记录**里把原版抢救回来（纯属侥幸）。→ 纪律三条：① **新写的机制当轮提交**（至少 `git add` 让它进 index）；② 口径变更后**立刻中断**旧口径的代理（`interrupt_agent`），不要让它"跑完"；③ **委派前先确认没有兄弟代理在做同一任务**（这次是我重复委派导致两个写者）。门禁：无（靠流程），但收尾时要求 `git status` 干净的理由更硬了。
208. **同版本"在线升级"必然被拒**：改完代码想在本机验证时，若 `version.go` 没变，`POST /system/upgrade/check` 返回 `has_update=false`、`stage` 说"当前已是最新版本"、`apply` 报"还没有已准备好的升级包"——**看着像升级功能坏了，其实是版本号没变**（`handleUpgradeApply` 有 sameVersion 校验）。→ 本机自测固定流程：`make bump` → `make check` → `make release ARCHS=arm64` → `make mirror-public` → 发布到本机镜像站 → 临时源 8791 → `upgrade/check|stage|apply` → health 读到新版本。另：在线升级只替换 `zizpanel`/`zizpanel-helper`，**不会刷新随包模块的二进制**（如 `/opt/zizpanel/bin/zizvideo`），这类模块要么进 swap 列表、要么由模块自己的安装流程更新。
209. **单测夹具指向真实外置卷 ⇒ 拔盘就红**：zizvideo 的 `TestSetRootsPreservesOtherFields` 拿 `/Volumes/ZPMirror/video`（作者的媒体盘）当"合法根"夹具，2026-09-20 把盘摘下来准备迁到生产机后，`make check` 立刻停在 `拒绝写入 /Volumes/ZPMirror/video: 路径不存在` —— 看着像新功能回归，其实是**环境依赖**（`SetRoots` 会校验目录真实存在）。→ 规矩：单测夹具只用 `t.TempDir()`；外置卷/受保护目录只许真机验证，绝不进单测。同一类一起筛过：全仓 `_test.go` 里 `/Volumes/` 只剩面板侧的 **stub 字符串**（`stubDiskVolumeAuth` 之类，不真访问）。门禁：`TestTestFixturesAvoidRealVolumes`（扫 zizvideo 全模块 `_test.go`，出现 `/Volumes/` 即红）。
