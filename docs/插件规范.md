# 应用插件规范（zizpanel.app/v1）

> 目的：把"面板的能力与权限"（安装、托管运行、探针、入口、卸载、更新）从 Go 代码里抽出来，
> 变成**一张签名的表**。新增应用 = 填表 + 一条校验命令，而不是再写一套安装器 + 探针 + 门禁。
> 现状：**P0 已完成**（规范 + `zizpanel plugin validate|plan` + alist/syncthing 两份真实声明）；
> **P1（B1 双记账）已完成**：表已驱动卡片事实（`Catalog()` → `applyPluginTable`），
> 并有逐字段等价性门禁看住它与手写目录不漂移（`internal/services/plugin_equiv_test.go`）。
> 路线图见 `docs/平台化路线图.md`。

---

## 一、铁律：插件只是数据，绝不允许携带代码

面板是 **root 守护进程**，能装插件的入口等于代码执行权。所以：

1. 结构体里没有任何"跑一段命令/脚本"的字段；解码用 `DisallowUnknownFields`，
   出现 `steps` / `script` / `command` / `post_install_script` 之类未知键**当场报错**。
2. 需要定制逻辑的动作（例：Syncthing 改 GUI 监听 + 设随机口令）只能引用**面板内建补丁名**，
   名字不在白名单里直接拒绝（当前白名单：`syncthing-gui-lan`、`filebrowser-root`、
   `transmission-rpc`、`miniflux-provision`）。
3. 远端插件（P3）必须**签名**（复用现有的 Ed25519 清单机制）；未签名/签名无效一律拒绝。
4. 安装前要把 `requires` 里的权限列成一张**同意清单**给用户看（FDA、可移除宗卷、本地网络、端口、系统守护进程）。

## 二、字段表

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | ✅ | 固定 `zizpanel.app/v1` |
| `id` / `name` / `icon` | ✅ | `id` 小写字母数字连字符（≤32）；`icon` 给市场卡片用 |
| `summary` / `notes[]` | | 一句话简介 + 给用户看的安装说明（每条一句话） |
| `source` | ✅ | `kind`: `brew` / `release` / `compose`；各自的必填项见下 |
| `source.checksum` | 重要 | `sha256` / `md5` / `arch-only` —— **必须如实声明校验强度**（alist 上游只有 md5，就写 `md5`，不许假装 sha256） |
| `run.mode` | ✅ | `panel-daemon`（面板托管，**继承面板 TCC 授权**）/ `app-daemon`（launchd 直接跑应用）/ `brew-service` / `compose` / `none` |
| `run.supervise` | panel-daemon 必填 | `{bin, args[], subcmd?, log_dir?, work_dir?}`；`subcmd` 默认 `<id>-supervise` |
| `run.hooks[]` | | 只能引用面板**内建补丁名** |
| `config` | | `{path, seed?, mode?=0600, secrets[]?, own?=user, format?, section?, set?, if_missing?}`；`seed` 是插件目录里的模板文件 |
| `config.secrets[]` | | 🆕 与 `set` 同处声明：这些键的值**由面板随机生成、只展示一次**（写进安装结果的凭据区）。**已有非空值一律复用、绝不轮换**（重装换口令 = 把应用弄坏）；写盘失败时凭据区清空（不让用户拿到一个不在配置里的口令） |
| `config.patches[]` | | 🆕 一个文件要改**多个 section** 时用它（每项就是一份 `{format?, section?, set?, secrets?, if_missing?}`）；与上面的单补丁简写二选一 |
| `config.set` | | 🆕 **声明式配置补丁**（2026-09-24）：`{"http_port": "3002"}` 这样声明"装上之后改这些键"。`format` = `kv`（默认）/ `ini` / `yaml`，`section` 只在 ini 里有意义，`if_missing` = `skip`（默认）/ `create`。**只换值**：缩进、分隔符写法、行尾注释、其它键与注释原样保留；改动前留一份 `<file>.zizpanel.bak`。值里不许有换行（否则等于允许注入任意配置行，校验直接拒绝）。有了它，"只差一行配置"的应用（改监听端口/地址）才能靠填表上架 —— grafana 就是第一个（默认 3000 撞 Gitea → 改成 3002） |
| `expose` | | `{port?, bind?=0.0.0.0, ui_port?, ui?: panel-hosted\|app, path?}`；`bind` 只允许 `0.0.0.0` / `127.0.0.1` |
| `verify.any_of[]` | ✅ | 安装收尾**真的跑一次**的探针，任一通过即可；四类：`http` / `rpc` / `process` / `port` |
| `health` | ✅ | 列表与卡片"运行中"的判据来源（含 `interval`）。**必填**：没有它只能显示"未复核"，那等于把假状态留给用户 |
| `uninstall` | ✅ | `{always[]（一定删）, optional_data[]（勾选「删除数据」才删）, formula?, keep_note?}` |
| `update` | | `brew` / `release-index` / `none` |
| `requires` | | `full_disk` / `removable_volume` / `local_network` / `system_daemon` / `ports[]` … |

**探针四类**（够覆盖目前所有应用）：

```jsonc
{ "kind": "http",    "path": "/healthz", "expect": "ok" }          // 期望响应体含子串
{ "kind": "rpc",     "url": "http://127.0.0.1:6800/jsonrpc",       // 只允许打本机回环
                     "method": "aria2.getVersion", "secret_ref": "rpc-secret", "expect_key": "version" }
{ "kind": "process", "label": "com.zizdog.alist" }                 // 只证明"进程在跑"
{ "kind": "port",    "port": 8384 }                                // 只证明"端口在听"
```

⚠️ `process` / `port` 是**弱判据**：卡片必须如实写"进程在跑"，不许写成"服务正常"。
（aria2 那次"卡死却显示运行中"就是这么来的 —— 有 `rpc` 探针可用时就用 `rpc`。）

## 三、本地插件（P2，已实现）

把一份 JSON 放进**插件目录**（面板里 `GET /api/v1/plugins` 会告诉你确切路径；默认 `<安装根>/plugins`，
即 `/opt/zizpanel/plugins`），然后在面板里**显式启用**，它就会作为一张正常的应用卡片出现在应用市场里。

```bash
zizpanel plugin init --out /opt/zizpanel/plugins/myapp.json   # 生成模板
$EDITOR /opt/zizpanel/plugins/myapp.json                      # 改 id/name/formula/端口/健康路径
zizpanel plugin validate /opt/zizpanel/plugins/myapp.json      # 校验（不碰机器）
zizpanel plugin plan     /opt/zizpanel/plugins/myapp.json      # 干跑：会做什么
# 面板里：应用市场 → 本地插件 → 启用（之后就能像自带应用一样安装/启停/卸载）
```

规则（都是有意的）：

| 规则 | 为什么 |
|---|---|
| **默认关闭**，必须显式启用 | 插件等于让面板以 root 去装/跑东西 |
| `id` 不许与面板自带应用重名 | 否则会"覆盖"自带条目，行为不可预期 |
| 目前只支持 `source.kind=brew`（`brew-service` / `app-daemon` / `none`） | 只有这条轨有现成的通用实现；其它来源会在列表里如实写"JSON 装载还没做"（B4），**不许假装能装** |
| 解析/校验失败的文件**照样列出来**并带原因 | "放进去了却什么都不发生"是最难查的形态 |
| 启用状态写在插件目录的 `enabled.json`（0600） | 与插件文件放一起，备份/迁移时状态跟着走；不写进面板配置（两份真源必漂） |
| 停用 ≠ 卸载 | 停用只是不再显示/不再安装，**已装的东西仍在机器上** |
| **表的能力边界（2026-09-24 更新）**：`config.set` **已经真的会执行**（安装路径在 `brew services start` 之前应用，见 `services/applyConfigPatchStep`）⇒ 「改一行配置」这类应用可以填表上架了（grafana）。`config.secrets` **也已经会执行**（随机口令写进配置 + 只展示一次 + 已有值复用不轮换）。仍未实现的是 `config.seed`（模板文件）与 `run.hooks`（**只有名字、没有执行通路** —— syncthing 的局域网补丁仍是手写 Go）。所以**能上架的插件 = 零定制，或"改键值 + 生成随机口令"能表达的应用**；需要执行定制动作（syncthing 那种改 XML 结构、miniflux 那种建库跑迁移）的仍不许写进表里 |

## 四、远端插件（B3，已实现）

从**签名目录**里取插件（默认关闭，必须显式给地址；落盘后仍然是"未启用"，还要在面板里再点一次启用）：

```bash
# 目录格式：<源>/plugins/index.json(.sig)，签名用与面板升级同一把 Ed25519 发布公钥
zizpanel plugin remote list    --source https://mirror.zizdog.com:8888/plugins/index.json
zizpanel plugin remote install myapp --source …/index.json        # 先打印计划与权限清单，要求 --yes
zizpanel plugin remote remove  myapp --dir /opt/zizpanel/plugins
```

信任模型（四道，缺一不可）：

| 关卡 | 为什么 |
|---|---|
| 目录**必须验签**（内嵌发布公钥，唯一信任根） | 没签名/签名不对一律不认，连解析都不做 |
| 声明本体按 **sha256** 核对 | 签名只覆盖目录，不覆盖它指向的文件 |
| 声明落盘前过**同一套**严格校验（未知键拒绝） | 远端声明不比本地声明更可信 |
| **双重确认** + id 不许撞车 | 默认关闭；`--yes` 才落盘；落盘后仍"未启用"；撞自带应用/已有插件直接拒绝 |

目录格式：

```jsonc
{ "schema": "zizpanel.plugins/v1", "generated_at": "2026-09-23T…",
  "plugins": [ { "id": "myapp", "name": "我的应用", "icon": "🧩", "version": "1.2.3",
                 "url": "myapp.json",        // 相对目录地址或绝对 URL
                 "sha256": "<该文件的 sha256>" } ] }
```

门禁：`TestRemoteInstallHappyPath`（正路：验签→哈希→校验→落盘 0600→**未启用**→来源记录→可移除）、
`TestRemoteRejectsBadSignature`（没信任根 / 内容被改 / 换钥匙，三种都拒）、
`TestRemoteRejectsTamperedSpec`（声明哈希不符，且不留半成品）、`TestRemoteRefusesReservedID`、
`TestRemoteIndexRequiresSource`（默认关闭，绝不偷偷联网）、`TestRemoteInvalidSpecRejected`。

## 五、用表新增应用（B4，已落地）

内建表（`internal/plugins/builtin/*.json`）里**目录里没有**的条目会被自动追加进应用目录 ——
这就是"填表就能加应用"的兑现点。目前用这条路新增了三个 brew 服务型应用：
`redis`（6379）、`mosquitto`（1883）、`memcached`（11211）。

加一个应用要碰的东西（**同一轮全部做完**，否则现有门禁会当场拦住 —— 它们就是这么设计的）：

| 步骤 | 门禁 |
|---|---|
| 写 `internal/plugins/builtin/<id>.json` | `zizpanel plugin validate` + `TestBuiltinSpecsAreValid` |
| `market_downloads.go` 补下载点声明 | `TestMarketDeclarationsCoverCatalogExactly` / `TestMarketInvariantsHold` |
| 服务型应用要进 `systemdaemon.go` 的判断清单 | `TestSystemDaemonFlagMatchesJudgment` |
| 有 brew formula 时确认它自带 service 块 | 人工：`brew info --json=v2 <formula>` 看 `service`（别猜） |
| 端口/健康路径的准确性 | `TestBuiltinTableOnlyAppsReachCatalog`（端口/健康/系统守护/`{brew}` 展开） |

路径占位符：`~/…` 按真实家目录展开，`{brew}/…` 按本机 Homebrew 前缀展开
（Apple Silicon `/opt/homebrew`、Intel `/usr/local` —— 写死前缀在另一种架构上就是错的）。

⚠️ **同一轨才允许覆盖**：表条目与目录条目 id 相同时，只有"来源/轨一致"才会覆盖卡片事实；
目录里是 compose/Docker（例如 gitea）而表里写 brew 时会被直接跳过 —— 那是两个不同的东西。

## 六、怎么用（CLI：P0 能力）

```bash
# 1) 写一份 <id>.json（照抄 docs/ 或 internal/plugins/testdata/ 里的例子）
# 2) 校验：只读文件，不碰机器
zizpanel plugin validate /path/to/alist.json
# 3) 干跑：打印"装这台机器会做什么"（来源/配置/服务怎么跑/入口/验收/卸载）
zizpanel plugin plan     /path/to/alist.json
```

`plan` 里最该看的两行：
- **服务怎么跑**：`panel-daemon` 会写明"继承面板的 TCC 授权"；`app-daemon` 会给出警告
  （数据目录若在 `~/Downloads`、`~/Desktop`、`~/Documents` 或外接卷，会被 macOS 隐私保护挡住）；
- **卸载删什么、留什么**：删的必须列清，用户数据默认保留。

## 七、示例：两种典型形态

**A. release 二进制 + launchd 直跑（alist）** —— `internal/plugins/testdata/alist.json`

```jsonc
{
  "schema": "zizpanel.app/v1", "id": "alist", "name": "Alist（文件列表）", "icon": "📂",
  "source": { "kind": "release", "repo": "AlistGo/alist", "tag": "v3.64.0",
              "asset": "alist-darwin-arm64.tar.gz", "binary": "alist",
              "targz": true, "pick_one": true, "checksum": "md5" },
  "run":    { "mode": "app-daemon", "bin": "~/alist/alist", "args": ["server", "--data", "~/alist/data"] },
  "config": { "path": "~/alist/data/config.json", "own": "user" },
  "expose": { "port": 5244, "bind": "0.0.0.0", "ui": "app" },
  "verify": { "any_of": [ { "kind": "http", "path": "/", "timeout": "60s" },
                          { "kind": "process", "label": "com.zizdog.alist" } ] },
  "health": { "kind": "http", "path": "/", "interval": "30s" },
  "uninstall": { "always": ["/Library/LaunchDaemons/com.zizdog.alist.plist"],
                 "optional_data": ["~/alist"] },
  "update": { "kind": "release-index" }
}
```

**B. brew + 服务化 + 内建补丁（syncthing）** —— `internal/plugins/testdata/syncthing.json`

```jsonc
{
  "schema": "zizpanel.app/v1", "id": "syncthing", "name": "Syncthing（文件同步）", "icon": "🔄",
  "source": { "kind": "brew", "formula": "syncthing", "checksum": "sha256" },
  "run":    { "mode": "brew-service", "hooks": ["syncthing-gui-lan"] },   // ← 定制逻辑引用内建补丁
  "config": { "path": "~/Library/Application Support/Syncthing/config.xml",
              "secrets": ["gui-user", "gui-password"] },
  "expose": { "port": 8384, "bind": "0.0.0.0", "ui": "app" },
  "verify": { "any_of": [ { "kind": "http", "path": "/rest/noauth/health", "expect": "ok" } ] },
  "health": { "kind": "http", "path": "/rest/noauth/health", "expect": "ok" },
  "uninstall": { "always": ["/Library/LaunchDaemons/homebrew.mxcl.syncthing.plist"],
                 "optional_data": ["~/Library/Application Support/Syncthing"],
                 "formula": "syncthing" },
  "requires": { "local_network": true, "system_daemon": true, "ports": [8384] }
}
```

## 八、门禁（P0–B4 已落地）

`internal/plugins/spec_test.go`：

| 门禁 | 抓什么 |
|---|---|
| `TestFixturesAreValid` | 两份真实声明必须过校验（"规范能不能覆盖现实"） |
| `TestFixturesMatchBuiltinCatalog` | 表与 Go 目录定义**不许漂移**（端口/健康路径/安装根）；P1 由表驱动目录后替换 |
| `TestUnknownKeysAreRejected` | 夹带 `post_install_script` / `run.steps` 等键必须被拒（安全边界） |
| `TestValidateRejectsUnsafeOrIncomplete` | 17 条不变量逐条负向对照（schema/id/checksum/supervise 绝对路径/bind/端口/回环/卸载路径/health/verify/hook 白名单…） |
| `TestLoadDirReportsInvalidInsteadOfHiding` / `TestEnabledStateRoundTrip` / `TestLoadDirMissingIsEmpty` | 本地插件：坏文件必须带原因列出、启用状态往返与 0600 权限、目录不存在是正常状态 |
| `TestLocalPluginStatusAndCatalog` / `TestLocalPluginCannotShadowBuiltin` / `TestLocalPluginAppRejectsUnsupported` | 映射层：启用才进目录、撞 id 拒绝、不支持的来源如实报原因 |
| `TestPluginEndpointsListAndToggle` / `TestPluginToggleRefusesUninstallable` / `TestPluginEndpointsRequireAuth` | 接口层：填表→启用→市场出现→停用消失；不可装的启用被拒；未登录 401 |
| `TestRemote*`（6 条） | 远端插件：验签/哈希/严格校验/撞 id/默认关闭/不留半成品 |
| `TestBuiltinTableOnlyAppsReachCatalog` | 表驱动新增应用：只在表里的条目必须真的进目录（端口/健康/系统守护/`{brew}` 展开），release 轨映射不出来就不塞半成品 |

**B1 双记账门禁**（`internal/services/plugin_equiv_test.go`，与手写目录对照）：

| 门禁 | 抓什么 |
|---|---|
| `TestPluginTableMatchesCatalog` | 表 vs 目录：名称/图标/摘要/端口/健康路径/配置文件（比解析后的绝对路径）/brew formula |
| `TestPluginTableMatchesUninstallPlan` | 表 vs `PlanUninstallFor` 真实计划：可选删数据路径、formula |
| `TestPluginTableDrivesCatalogWithoutChangingIt` | 接线后**零变化**：`Catalog()` 与手写定义逐字段相同；未进表的条目原样透传 |
| `TestPluginEquivCatchesDrift` | 负向对照：改表里的端口/卸载路径必须被判出来 |
