# 应用插件规范（zizpanel.app/v1）

> 目的：把"面板的能力与权限"（安装、托管运行、探针、入口、卸载、更新）从 Go 代码里抽出来，
> 变成**一张签名的表**。新增应用 = 填表 + 一条校验命令，而不是再写一套安装器 + 探针 + 门禁。
> 现状：**P0 已完成**（规范 + `zizpanel plugin validate|plan` + alist/syncthing 两份真实声明）；
> **P1（B1 双记账）已完成**：表已驱动卡片事实（`Catalog()` → `applyPluginTable`），
> 并有逐字段等价性门禁看住它与手写目录不漂移（`internal/services/plugin_equiv_test.go`）。
> 路线图见 `docs/平台化路线图.md`。

---

## 一、铁律：插件只是数据，绝不允许携带代码

面板是 **root 守护进程**，能装插件的入口等于代码执行权。所以：

1. 结构体里没有任何"跑一段命令/脚本"的字段；解码用 `DisallowUnknownFields`，
   出现 `steps` / `script` / `command` / `post_install_script` 之类未知键**当场报错**。
2. 需要定制逻辑的动作（例：Syncthing 改 GUI 监听 + 设随机口令）只能引用**面板内建补丁名**，
   名字不在白名单里直接拒绝（当前白名单：`syncthing-gui-lan`、`filebrowser-root`、
   `transmission-rpc`、`miniflux-provision`）。
3. 远端插件（P3）必须**签名**（复用现有的 Ed25519 清单机制）；未签名/签名无效一律拒绝。
4. 安装前要把 `requires` 里的权限列成一张**同意清单**给用户看（FDA、可移除宗卷、本地网络、端口、系统守护进程）。

## 二、字段表

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | ✅ | 固定 `zizpanel.app/v1` |
| `id` / `name` / `icon` | ✅ | `id` 小写字母数字连字符（≤32）；`icon` 给市场卡片用 |
| `summary` / `notes[]` | | 一句话简介 + 给用户看的安装说明（每条一句话） |
| `source` | ✅ | `kind`: `brew` / `release` / `compose`；各自的必填项见下 |
| `source.checksum` | 重要 | `sha256` / `md5` / `arch-only` —— **必须如实声明校验强度**（alist 上游只有 md5，就写 `md5`，不许假装 sha256） |
| `run.mode` | ✅ | `panel-daemon`（面板托管，**继承面板 TCC 授权**）/ `app-daemon`（launchd 直接跑应用）/ `brew-service` / `compose` / `none` |
| `run.supervise` | panel-daemon 必填 | `{bin, args[], subcmd?, log_dir?, work_dir?}`；`subcmd` 默认 `<id>-supervise` |
| `run.hooks[]` | | 只能引用面板**内建补丁名** |
| `config` | | `{path, seed?, mode?=0600, secrets[]?, own?=user}`；`seed` 是插件目录里的模板文件 |
| `expose` | | `{port?, bind?=0.0.0.0, ui_port?, ui?: panel-hosted\|app, path?}`；`bind` 只允许 `0.0.0.0` / `127.0.0.1` |
| `verify.any_of[]` | ✅ | 安装收尾**真的跑一次**的探针，任一通过即可；四类：`http` / `rpc` / `process` / `port` |
| `health` | ✅ | 列表与卡片"运行中"的判据来源（含 `interval`）。**必填**：没有它只能显示"未复核"，那等于把假状态留给用户 |
| `uninstall` | ✅ | `{always[]（一定删）, optional_data[]（勾选「删除数据」才删）, formula?, keep_note?}` |
| `update` | | `brew` / `release-index` / `none` |
| `requires` | | `full_disk` / `removable_volume` / `local_network` / `system_daemon` / `ports[]` … |

**探针四类**（够覆盖目前所有应用）：

```jsonc
{ "kind": "http",    "path": "/healthz", "expect": "ok" }          // 期望响应体含子串
{ "kind": "rpc",     "url": "http://127.0.0.1:6800/jsonrpc",       // 只允许打本机回环
                     "method": "aria2.getVersion", "secret_ref": "rpc-secret", "expect_key": "version" }
{ "kind": "process", "label": "com.zizdog.alist" }                 // 只证明"进程在跑"
{ "kind": "port",    "port": 8384 }                                // 只证明"端口在听"
```

⚠️ `process` / `port` 是**弱判据**：卡片必须如实写"进程在跑"，不许写成"服务正常"。
（aria2 那次"卡死却显示运行中"就是这么来的 —— 有 `rpc` 探针可用时就用 `rpc`。）

## 三、怎么用（当前 P0 能力）

```bash
# 1) 写一份 <id>.json（照抄 docs/ 或 internal/plugins/testdata/ 里的例子）
# 2) 校验：只读文件，不碰机器
zizpanel plugin validate /path/to/alist.json
# 3) 干跑：打印"装这台机器会做什么"（来源/配置/服务怎么跑/入口/验收/卸载）
zizpanel plugin plan     /path/to/alist.json
```

`plan` 里最该看的两行：
- **服务怎么跑**：`panel-daemon` 会写明"继承面板的 TCC 授权"；`app-daemon` 会给出警告
  （数据目录若在 `~/Downloads`、`~/Desktop`、`~/Documents` 或外接卷，会被 macOS 隐私保护挡住）；
- **卸载删什么、留什么**：删的必须列清，用户数据默认保留。

## 四、示例：两种典型形态

**A. release 二进制 + launchd 直跑（alist）** —— `internal/plugins/testdata/alist.json`

```jsonc
{
  "schema": "zizpanel.app/v1", "id": "alist", "name": "Alist（文件列表）", "icon": "📂",
  "source": { "kind": "release", "repo": "AlistGo/alist", "tag": "v3.64.0",
              "asset": "alist-darwin-arm64.tar.gz", "binary": "alist",
              "targz": true, "pick_one": true, "checksum": "md5" },
  "run":    { "mode": "app-daemon", "bin": "~/alist/alist", "args": ["server", "--data", "~/alist/data"] },
  "config": { "path": "~/alist/data/config.json", "own": "user" },
  "expose": { "port": 5244, "bind": "0.0.0.0", "ui": "app" },
  "verify": { "any_of": [ { "kind": "http", "path": "/", "timeout": "60s" },
                          { "kind": "process", "label": "com.zizdog.alist" } ] },
  "health": { "kind": "http", "path": "/", "interval": "30s" },
  "uninstall": { "always": ["/Library/LaunchDaemons/com.zizdog.alist.plist"],
                 "optional_data": ["~/alist"] },
  "update": { "kind": "release-index" }
}
```

**B. brew + 服务化 + 内建补丁（syncthing）** —— `internal/plugins/testdata/syncthing.json`

```jsonc
{
  "schema": "zizpanel.app/v1", "id": "syncthing", "name": "Syncthing（文件同步）", "icon": "🔄",
  "source": { "kind": "brew", "formula": "syncthing", "checksum": "sha256" },
  "run":    { "mode": "brew-service", "hooks": ["syncthing-gui-lan"] },   // ← 定制逻辑引用内建补丁
  "config": { "path": "~/Library/Application Support/Syncthing/config.xml",
              "secrets": ["gui-user", "gui-password"] },
  "expose": { "port": 8384, "bind": "0.0.0.0", "ui": "app" },
  "verify": { "any_of": [ { "kind": "http", "path": "/rest/noauth/health", "expect": "ok" } ] },
  "health": { "kind": "http", "path": "/rest/noauth/health", "expect": "ok" },
  "uninstall": { "always": ["/Library/LaunchDaemons/homebrew.mxcl.syncthing.plist"],
                 "optional_data": ["~/Library/Application Support/Syncthing"],
                 "formula": "syncthing" },
  "requires": { "local_network": true, "system_daemon": true, "ports": [8384] }
}
```

## 五、门禁（P0 已落地）

`internal/plugins/spec_test.go`：

| 门禁 | 抓什么 |
|---|---|
| `TestFixturesAreValid` | 两份真实声明必须过校验（"规范能不能覆盖现实"） |
| `TestFixturesMatchBuiltinCatalog` | 表与 Go 目录定义**不许漂移**（端口/健康路径/安装根）；P1 由表驱动目录后替换 |
| `TestUnknownKeysAreRejected` | 夹带 `post_install_script` / `run.steps` 等键必须被拒（安全边界） |
| `TestValidateRejectsUnsafeOrIncomplete` | 17 条不变量逐条负向对照（schema/id/checksum/supervise 绝对路径/bind/端口/回环/卸载路径/health/verify/hook 白名单…） |

**B1 双记账门禁**（`internal/services/plugin_equiv_test.go`，与手写目录对照）：

| 门禁 | 抓什么 |
|---|---|
| `TestPluginTableMatchesCatalog` | 表 vs 目录：名称/图标/摘要/端口/健康路径/配置文件（比解析后的绝对路径）/brew formula |
| `TestPluginTableMatchesUninstallPlan` | 表 vs `PlanUninstallFor` 真实计划：可选删数据路径、formula |
| `TestPluginTableDrivesCatalogWithoutChangingIt` | 接线后**零变化**：`Catalog()` 与手写定义逐字段相同；未进表的条目原样透传 |
| `TestPluginEquivCatchesDrift` | 负向对照：改表里的端口/卸载路径必须被判出来 |
